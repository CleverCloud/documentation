## Overview

[Elixir](https://elixir-lang.org) is a functional language that runs on the Erlang virtual machine, built for concurrent and fault-tolerant applications. Clever Cloud builds your [Mix](https://hexdocs.pm/mix/) project. It starts [Phoenix](https://www.phoenixframework.org) web applications by default, and any other project, such as a [Plug](https://hexdocs.pm/plug/) server, with the task you set.

## Create your Elixir application

To create a new Elixir application, use the [Clever Cloud Console](https://console.clever-cloud.com) or [Clever Tools](https://github.com/CleverCloud/clever-tools):

```bash
clever create --type elixir
```

- [Learn more about Clever Tools](/doc/tools/cli/)
- [Learn more about Clever Cloud application deployment](/doc/getting-started/#create-an-application-step-by-step)

## Configure your Elixir application

### Mandatory needs

An Elixir application needs:

- A `mix.exs` file and its `mix.lock` file, at the root of the project or of the folder set in `APP_FOLDER`
- A web server listening on `0.0.0.0`, on [the port in `PORT`](/doc/manage/#listen-on-the-right-port)

Mix is the build tool of Elixir. `mix.exs` describes your project and its dependencies. `mix deps.get` records their exact versions in `mix.lock`: commit it, so that the build fetches the versions you tested. A [Clever Task](#elixir-applications-as-clever-tasks) doesn't need a web server.

A Phoenix application generated by `mix phx.new` reads `PORT` in `config/runtime.exs`, and listens on every interface in production. It also needs, in the environment of your application:

- `MIX_ENV=prod`, which builds and runs the production configuration
- `SECRET_KEY_BASE`, a secret generated with `mix phx.gen.secret`
- `PHX_HOST`, the domain name of your application, which Phoenix uses to build its URLs

```bash
clever env set MIX_ENV prod
clever env set SECRET_KEY_BASE "$(mix phx.gen.secret)"
clever env set PHX_HOST myapp.cleverapps.io
```

Your application reads its [environment variables](/doc/manage/environment-variables/) with `System.get_env`, in `config/runtime.exs` or in its code, such as add-on credentials.

Phoenix reads the URL of its database in `DATABASE_URL`, through [Ecto](https://hexdocs.pm/ecto/), but a linked [PostgreSQL add-on](/doc/deploy/databases/postgresql/) provides `POSTGRESQL_ADDON_URI`. In `config/runtime.exs`, replace the `database_url` assignment with this one, and keep the rest:

```elixir {filename="config/runtime.exs"}
database_url =
  System.get_env("DATABASE_URL") || System.get_env("POSTGRESQL_ADDON_URI") ||
    raise "environment variable DATABASE_URL is missing"
```

### Build phase

On a new build, Clever Cloud selects the [Elixir and Erlang/OTP versions](#elixir-and-erlangotp-versions) and runs the pre-build [hook](/doc/manage/build-hooks/). It then installs [Hex](https://hex.pm), the package manager, and Rebar, the Erlang build tool. Finally, it fetches and compiles your dependencies, and builds your project:

```bash
mix local.hex --force
mix local.rebar --force
mix deps.get
mix deps.compile
npm install
mix compile
npm run deploy
```

npm builds the web assets of projects that use it, from their `package.json` file, in the folder set in `CC_PHOENIX_ASSETS_DIR`, the root of the project by default. Without this file, npm logs an error, and the build goes on.

To run another Mix task instead of `mix compile`, set it in `CC_MIX_BUILD_GOAL`.

### Build Phoenix assets

A Phoenix application created by `mix phx.new` builds its JavaScript and CSS with `assets.deploy`, an alias for several Mix tasks. To run it during the build, add a `cc.build` alias to the `aliases` list of `mix.exs`, and keep the others.

This alias compiles the project, then builds the assets:

```elixir {filename="mix.exs"}
defp aliases do
  [
    # Keep the aliases mix phx.new generated, and add:
    "cc.build": ["compile", "assets.setup", "assets.deploy"]
  ]
end
```

Then run it instead of `mix compile`:

```bash
clever env set CC_MIX_BUILD_GOAL cc.build
```

### Elixir and Erlang/OTP versions

Elixir runs on the virtual machine and libraries of Erlang/OTP. Clever Cloud uses `CC_ELIXIR_VERSION`, with the matching OTP version:

{{< runtimes_versions elixir >}}

To use Elixir 1.18 and Erlang/OTP 27, for instance:

```bash
clever env set CC_ELIXIR_VERSION 1.18
```

### Start phase

Before it starts your application, Clever Cloud installs Hex and Rebar again, and prepares Phoenix and its database:

- `mix phx.digest` adds a fingerprint to the names of the static files, so that browsers load their new versions
- `mix ecto.migrate` runs the [Ecto](https://hexdocs.pm/ecto/) migrations, which update the structure of your database
- `mix phx.server` starts Phoenix

Each of these steps has its own variable:

- `CC_PHOENIX_DIGEST_GOAL` replaces `mix phx.digest` with another Mix task
- `CC_PHOENIX_RUN_ECTO_MIGRATE=false` skips `mix ecto.migrate`
- `CC_PHOENIX_APP_DIR` sets the folder of the migrations, the root of the project by default
- `CC_PHOENIX_SERVER_GOAL` replaces `mix phx.server` with another Mix task
- `CC_RUN_COMMAND` replaces it with a whole command, run from the root of the repository

The migrations run on every start of every instance. If the digest or the migrations fail, Mix logs an error, and the start goes on.

A Mix project without Phoenix, such as a Plug server, has no `mix phx.server` task: set its start task, otherwise the deployment fails. Without Phoenix and Ecto, also replace the digest with a task that does nothing more, such as `compile`, and skip the migrations:

```bash
clever env set CC_PHOENIX_SERVER_GOAL "run --no-halt"
clever env set CC_PHOENIX_DIGEST_GOAL compile
clever env set CC_PHOENIX_RUN_ECTO_MIGRATE false
```

### Caches

After a successful build of an application, Clever Cloud keeps a build cache of the commit. Restarting the application without a code change reuses it and skips the build. To build again from scratch, restart without the cache (rebuild):

```bash
clever restart --without-cache
```

With `CC_CACHE_DEPENDENCIES=true`, Clever Cloud also keeps the `deps` and `_build` folders at the root of the repository, Hex and Rebar, and the npm cache between commits, so the next builds fetch and compile fewer dependencies.

## Elixir applications as Clever Tasks

An Elixir application can run as a [Clever Task](/doc/deploy/tasks/), such as a job or a migration: Clever Cloud builds it, then runs `CC_RUN_COMMAND`, without the digest and the migrations. The command runs from the root of the repository.

Configure Tasks from the `Information` panel in [the Console](https://console.clever-cloud.com) or with [Clever Tools](/doc/tools/cli/applications/#tasks), here for a `priv/tasks/report.exs` script:

```bash
clever create --type elixir --task "mix run priv/tasks/report.exs"
clever deploy # or clever restart if there is no code change
```
